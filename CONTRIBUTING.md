# Contributing

Thanks for contributing to Formbase.

## Before you open a PR

- For non-trivial work, open an issue or start with a short proposal first.
- Keep PRs focused. Do not mix refactors, formatting, and feature work in one change.
- Avoid speculative cleanup PRs without a clear problem statement.

## Development expectations

- Run the relevant tests, build steps, and typechecks for the area you changed.
- Add or update tests for behavior changes.
- Keep docs and examples in sync when public behavior changes.
- Preserve existing code style and naming unless the change intentionally standardizes something small and scoped.

## AI/tooling-assisted contributions

Tooling is allowed, but contributors are still responsible for the result.

If you used AI or other code-generation tooling:

- review every changed line yourself
- explain what the change does and why it is correct
- call out any parts that need extra reviewer attention
- do not submit bulk-generated refactors without a clear issue and validation

Low-context, mass-generated, or poorly validated changes may be closed without merge.

## Pull request guidelines

- Link the issue or explain the motivation.
- Describe the user-facing or developer-facing impact.
- Include screenshots or recordings for UI changes when helpful.
- Mention follow-up work separately instead of bundling it into the same PR.

## Security

Please do not open public issues for suspected security vulnerabilities.
See `SECURITY.md` for reporting guidance.
